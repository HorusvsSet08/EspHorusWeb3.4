Montaje: Cómo construir la estación Horus

Guía práctica paso a paso para montar, cablear, configurar y poner en servicio la estación meteorológica.

¿Qué objetivo tiene esta guía?

Explicar de forma clara y reproducible cómo montar la estación Horus: componentes necesarios, conexión eléctrica y de sensores, configuración del firmware (ESP/Arduino), puesta en red vía MQTT, calibración y pruebas. Está pensada para alguien con conocimientos básicos de electrónica y programación embedded.

¿Qué componentes necesito?

  • Controlador: ESP32 (recomendado) o ESP8266 / Arduino + módulo Wi-Fi.
  • Sensores:
    • Temperatura y humedad: SHT31 / DHT22 (SHT31 recomendado por precisión).
    • Presión atmosférica: BMP388 o BME280 (BME280 incluye humedad).
    • Viento: anemómetro (salida impulsos o analógica) y veleta (potenciómetro o sensor magnético).
    • Precipitación: pluviómetro (taza basculante con interruptor reed).
    • Calidad del aire: sensor PM2.5/PM10 (SDS011, PMS7003 o similares).
    • Nivel de gas (opcional): MQ-135 u otro sensor de gases.
  • Fuente de alimentación: 5V/3A o fuente según consumo total; regulator si usas 12V solar/batería.
  • Batería / Energía solar (opcional): panel solar + controlador de carga + batería de 12V/7Ah según autonomía deseada.
  • Caja/Estación meteorológica: carcasa IP65 para electrónica, mástil o poste para sensores, ventilación aspirada si es necesario.
  • Elementos mecánicos: abrazaderas, tornillos inox, junta de silicona, mástil, soportes.
  • Herramientas: soldador, estaño, multímetro, pelacables, destornilladores, taladro, cinta aislante termo-retráctil.

¿Qué documentación/archivos de firmware necesitaré?

  • Firmware para ESP32 que lea sensores y publique en MQTT (ej. basado en Arduino/PlatformIO o ESPHome).
  • Script de calibración y escalado para anemómetro/veleta y pluviómetro.
  • Credenciales Wi-Fi y configurador de topics MQTT.
  • Fichas técnicas (datasheets) de sensores para tensiones y pines.

¿Cómo se cablea la estación? (Esquema general)

Descripción general: los sensores conectan al microcontrolador (I²C, UART, digital), la alimentación alimenta todo y el micro publica por MQTT.

Nota: revisa las tensiones: la mayoría de sensores I²C trabajan a 3.3V; evita alimentar sensores 5V al bus I²C sin conversión. Usa convertidores de nivel si es necesario.

¿Paso a paso: montaje físico?

  1. Prepara la carcasa: taladra los orificios para montaje del mástil, sellos y pasacables. Usa prensaestopas para sellado.
  2. Instala el microcontrolador: fija la placa en la carcasa sobre separadores; deja acceso a microUSB o entrada de alimentación.
  3. Ubica sensores en soportes adecuados: anemómetro y veleta en el mástil más alto; pluviómetro en un lugar sin obstrucciones; el sensor de temperatura/ humedad en una garita o pantalla radiaciona ventilada a ~1.5–2m del suelo.
  4. Cableado: lleva cables desde cada sensor hacia la caja. Utiliza conectores rápidos (JST) y protege las soldaduras con tubo termorretráctil.
  5. Alimentación: conecta la fuente a la entrada principal; si usas batería/solar, instala regulador y fusible.
  6. Comprueba polaridades y tensiones: con multímetro verifica 3.3V/5V, GND y continuidad de tierra.
  7. Sellado: aplica sellador en pasacables y junta de la tapa. Asegura ventilación pasiva para sensores sensibles (no hermetizar completamente).

¿Cómo programo el micro para enviar datos por MQTT?

Ejemplo mínimo (esquema): el micro lee sensores (I²C/UART/digital), construye JSON y lo publica en `horus/estacion/lecturas`.

Ejemplo (pseudocódigo / snippet Arduino para ESP32)


// Conexión WiFi y MQTT
#include <WiFi.h>
#include <PubSubClient.h>
#include <Wire.h>
// Includes de sensores (BME280, PMS, etc.)

const char* ssid = "TU_SSID";
const char* pass = "TU_PASS";
const char* mqtt_server = "broker.tu.dominio";
const int mqtt_port = 1883;
const char* topic = "horus/estacion/lecturas";

WiFiClient espClient;
PubSubClient client(espClient);

void setup() {
  Serial.begin(115200);
  WiFi.begin(ssid, pass);
  while (WiFi.status() != WL_CONNECTED) delay(500);
  client.setServer(mqtt_server, mqtt_port);
  // Init sensores (I2C, UART)
}

void loop() {
  if (!client.connected()) {
    // reconexión MQTT
  }
  // leer sensores
  float temp = obtenerTemperatura();
  float hum = obtenerHumedad();
  float pres = obtenerPresion();
  int pm25 = obtenerPM25();
  // construir JSON simple
  String payload = "{\"temp\": " + String(temp) + ", \"hum\": " + String(hum) + ", \"pres\": " + String(pres) + ", \"pm25\": " + String(pm25) + "}";
  client.publish(topic, payload.c_str());
  delay(15000); // publicar cada 15s (ajustable)
}

Consejo: usa QoS 1 si tu broker lo soporta para asegurar entrega, y añade timestamps (UTC). Si usas ESPHome, la configuración YAML tiene integraciones para los sensores más comunes y publica automáticamente en MQTT o a Home Assistant.

¿Cómo calibrar los sensores?

  • Temperatura / Humedad: compara con un instrumento de referencia conocido; aplica offset si es sistemático.
  • Presión: verifica con estaciones oficiales o servicios meteorológicos locales y aplica corrección por altitud.
  • Anemómetro: cuenta pulsos por segundo y aplica curva de calibración del fabricante (m/s por pulsos/s).
  • Pluviómetro: cada 'click' corresponde a un volumen conocido (ej. 0.2794 mm por click). Calibra con medición manual de lluvia.
  • PM2.5: compara con un sensor de referencia o estación cercana; los sensores ópticos necesitan tiempo de calentamiento y ajuste de offset.

Registra las constantes de calibración en tu firmware o en la base de datos para aplicar correcciones en el backend antes del análisis.

¿Qué topics / formato MQTT recomiendo?

Formato JSON compacto y topic por dispositivo/estación:


Topic: horus/estacion/{id}/telemetry
Payload: {
  "ts":"2025-11-17T10:12:00Z",
  "temp": 21.4,
  "hum": 55.2,
  "pres": 1013.8,
  "wind_speed": 3.6,
  "wind_dir": 245,
  "rain": 0.0,
  "pm25": 12
}

Usa un topic separado para eventos (alarma/batería baja) como `horus/estacion/{id}/status`.

¿Qué pruebas debo hacer antes de ponerla en producción?

  1. Comprobación de energía bajo diferentes condiciones (arranque con batería, desconexión de la red).
  2. Verificar estabilidad Wi-Fi y reconexión automática en pérdida de señal.
  3. Simular lecturas extremas y comprobar que el backend las recibe y registra.
  4. Revisión de integridad de datos (timestamps, zonas horarias, duplicados).
  5. Prueba de sellado y resistencia a lluvia y viento (si es posible en laboratorio o con agua controlada).

¿Mantenimiento y checklist periódico?

  • Revisión física trimestral: limpieza de sensores, revisado de tornillos y juntas.
  • Calibración anual o según deriva de sensores.
  • Actualizar firmware con seguridad: firma o versión controlada, y respaldos de configuración.
  • Comprobar consumo y salud de la batería cada 3–6 meses si es autónoma.

Preguntas frecuentes (FAQ)

¿Puedo usar otro microcontrolador distinto al ESP32?

Sí. ESP32 es recomendado por Wi-Fi robusto y potencia, pero puedes usar ESP8266 para proyectos simples o un Arduino con módulo Wi-Fi. Ten en cuenta recursos (RAM, UARTs, I2C) y compatibilidad con bibliotecas.

¿Cómo protejo la instalación contra rayos o sobretensiones?

Usa protección contra sobretensiones en la línea de alimentación, fusibles, y toma de tierra adecuada para el mástil. Evita conductores largos sin protección y usa varistores o supresores cuando corresponda.

Mi sensor PM muestra valores inestables, ¿por qué?

Los sensores ópticos se ven afectados por humedad, contaminación interna y el tiempo de calentamiento. Aísla la entrada de polvo con filtro, proporciona flujo de aire estable y realiza calibración cruzada.

Respaldo: checklist rápido antes del primer despliegue

  • Conexiones eléctricas firmes y polares correctas.
  • Sensores asegurados mecánicamente y a la altura correcta.
  • Firmware con Wi-Fi y MQTT configurados (credenciales correctas y broker accesible).
  • Comprobación de topics y formato JSON.
  • Protección climática y sellado correcto.
